Song Party

Local Multiplayer AI Party Game

Built a Jackbox-style local-network multiplayer party game with a real-time Node.js/WebSocket backend, an LLM-driven content-generation pipeline, and a third-party AI music API integration with automated content-policy remediation and multi-tier offline fallbacks.

  • Designed and built a real-time multiplayer web game (Node.js, Express, WebSocket) supporting an arbitrary number of concurrent phone clients against a single host display, with a server-authoritative state machine and per-client personalized broadcasts (each player receives only their own data over a shared connection pool).
  • Integrated the Anthropic Claude API to dynamically generate game content each round: player-specific prompts that combine into one coherent narrative, and full original song lyrics synthesized from crowd-sourced player answers — with automated self-verification (checks that every contributor is represented in the output, auto-correcting via a second model call before falling back to a deterministic template).
  • Designed a custom load-balancing algorithm to distribute a fixed question set across a variable number of players (1 to N), evenly splitting or cycling questions as needed and merging duplicate responses — verified correct across all group-size edge cases with automated tests.
  • Integrated a third-party generative audio API (ElevenLabs Music) to produce vocal music from AI-written lyrics and player-supplied style parameters, including automatic detection and one-shot remediation of content-policy rejections (stripping/paraphrasing flagged content and resubmitting) before falling back to a self-written, dependency-free procedural audio synthesizer.
  • Built a live debug/observability panel exposing raw request/response payloads for every external API call, enabling real-time verification of AI-generated vs. fallback content during testing and demos.
  • Implemented a lightweight feedback and analytics system: opt-in per-round ratings that trigger structured JSON logging of the full round context (prompts, answers, generated content, style parameters) for post-hoc review, persisted independently of in-memory game state.
  • Engineered for reliability under real third-party API constraints: request timeouts with abort handling, model-compatibility fixes across provider parameter changes, and layered fallbacks ensuring the game never hard-fails on an external service error.
  • Built the entire front end in vanilla JavaScript/CSS with no build step or framework, including a reactive rendering layer that avoids redundant re-renders to prevent data loss during concurrent user input on shared state updates.
